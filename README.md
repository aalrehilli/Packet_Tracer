# وصلة — مختبر الشبكات العربي

نسخة تأسيسية من مختبر ويب عربي باتجاه RTL لموضوعات **CCNA Introduction to Networks · ITN v7.02**، جاهزة للاستضافة على GitHub Pages، دون خادم خلفي أو اعتماديات تشغيل خارجية.

## ما الذي تعمل عليه النسخة؟

- فهرس يغطي أسماء الملفات الـ38 التي قدمها صاحب المشروع، مع البحث والتصفية حسب الوحدة.
- تدريبات عربية أصلية حسب موضوع كل نشاط، باستخدام شبكة تعليمية مشتركة: PC-A — S1 — R1 — S2 — PC-B.
- نموذج محدود لأوضاع IOS، وتهيئة واجهات IPv4 وIPv6، وأسماء الأجهزة، وحفظ التهيئة، وإعدادات SSH التعليمية.
- اختبار اتصال يعتمد على الوصلات وحالة الواجهات والعناوين والبوابات في الاتجاهين. نتائج Ping وTraceroute وARP تعليمية محسوبة داخل النموذج.
- توصيل الكابلات وفصلها، وتتبع مرئي تعليمي، وأسئلة فهم، وجداول IPv4 وVLSM وIPv6.
- حفظ محلي وإعادة جلسة الأوامر وتصدير التقدّم واستيراده. لا تزامن بين الأجهزة ولا حسابات مستخدمين.

## حدود مهمة

هذه **ليست إعادة إنتاج كاملة للأنشطة الأصلية**، وليست برنامج Cisco Packet Tracer في المتصفح. لم يتم فك ملفات PKA/PKT أو استخراج شبكاتها أو تعليماتها أو إجابات تقييمها. يستخدم كل صف من الفهرس تمرينًا موضوعيًا مبسطًا، وبعض الأنشطة تشترك في قالب تدريب واحد. تطابق الفهرس مع الملفات لا يعني تطابق محتوى المختبر معها.

لا تدعم النسخة استيراد PKA/PKT، أو IOS كاملًا، أو SSH/RSA فعليًا، أو شبكات لاسلكية، أو وضعًا فيزيائيًا ثلاثي الأبعاد. تتبع الحزم عرض تعليمي، لا محرك أحداث بروتوكولات كامل. نشاط الربط اللاسلكي مدرج بتمرين توصيل Ethernet فقط في هذه النسخة. لا تستخدم كلمات مرور حقيقية؛ الإعدادات التدريبية محفوظة محليًا وفي ملف التصدير.

لا تُنشر ملفات Cisco الأصلية في هذا المستودع. `inventory.json` يسجل أسماء الملفات وأحجامها فقط. التطبيق مستقل وغير تابع لـ Cisco أو معتمد منها.

## التشغيل محليًا

يلزم Node.js 22 أو أحدث:

```sh
npm test
npm run dev
```

افتح `http://127.0.0.1:4173`. لا تفتح `index.html` مباشرةً بنمط `file://` لأن التطبيق يستخدم وحدات JavaScript.

## النشر على GitHub Pages

يتضمن المشروع `.github/workflows/pages.yml` لاختبار النموذج ونشر `dist/` عند الدفع إلى `main`.

1. من إعدادات المستودع: **Settings → Pages → Source → GitHub Actions**.
2. من **Actions** شغّل **Test and deploy Arabic network lab** أو ادفع تعديلًا إلى `main`.
3. انتظر نجاح خطوة النشر. الرابط المتوقع للمستودع الحالي: `https://aalrehilli.github.io/Packet_Tracer/`.

يحاول إجراء التهيئة تمكين Pages تلقائيًا. إذا لم تسمح صلاحيات GitHub Actions بذلك، نفّذ الخطوة الأولى يدويًا ثم أعد تشغيل الإجراء. الرابط المتوقع ليس إثباتًا على نجاح النشر؛ راجع حالة Actions.

## تجربة سريعة

افتح **2.5.5**، واختر **S1**، ثم راجع التلميحات لتغيير الاسم وإعداد VLAN 1 والبوابة وحفظ التهيئة. في **10.3.5** اقرأ `ipconfig` على PC-A، أصلح البوابة من تبويب إعدادات الجهاز، ثم نفّذ `ping 192.168.20.10` و`tracert 192.168.20.10`.

## التوسّع نحو مطابقة المنهج

لإنجاز محاكي لكل نشاط بدقة يلزم توثيق كل ملف داخل Packet Tracer: المخطط، والمنافذ، والعناوين، والحالة الابتدائية، والخطوات، ومعايير النجاح. بعدها تُبنى سيناريوهات مستقلة وتُضاف سلوكيات المحاكاة المطلوبة ويُتحقق من كل نشاط. النسخة الحالية توفّر أساس الواجهة والنموذج والفهرس، ولا تدّعي اكتمال تلك المطابقة.

## هيكل المشروع

- `dist/labs.js`: فهرس الأنشطة وتمارينها الموضوعية.
- `dist/engine.js`: حالة الشبكة ومفسّر الأوامر ومعايير الإنجاز.
- `dist/app.js`: الواجهة والحفظ والتفاعل.
- `tests/engine.test.mjs`: اختبارات الحالة والاتصال والتغطية الاسمية.

احفظ التعديلات في `dist/` مباشرةً؛ لا توجد خطوة بناء.
